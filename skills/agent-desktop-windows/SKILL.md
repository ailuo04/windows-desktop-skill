# Windows 桌面操作

优先使用 `agent-desktop` MCP。先按应用名调用 `desktop_list_windows`，用返回的 `window_id` 限定后续查找。只有多个窗口都可能是目标时，才需要按标题或界面内容进一步区分。工具前缀可能随客户端而变化。

## 找到应用窗口

- 有目标窗口就直接读取，最小化时可按窗口 ID 还原。应用尚未运行时，通过已确认的程序名或本机安装路径启动；只有标题、关键词或用户输入的近似拼写时，先核对实际应用名。
- `desktop_launch` 返回 `AMBIGUOUS_TARGET` 时，重新按应用过滤窗口。Electron 的多个进程可能只对应一个窗口。没有窗口时，可通过 MCP 检查已显示的任务栏或托盘入口；找到对应项就唤出窗口并重新枚举。Windows 上 `no_attach` 无法解决已有实例的问题。
- 如果这些入口不可用，简要说明卡在哪一步。用户允许备用工具且当前权限允许时，仅用它唤出已安装的目标应用；窗口一出现就回到 MCP。用户明确要求只用 MCP 时，说明具体阻碍，请用户唤出窗口。遵守客户端的权限限制。

## 阅读、操作与核对

- 已知控件文字时优先 `desktop_find`，结合 `name`、`role` 和窗口 ID。需要辨别“立即领取”属于哪项活动时，读取同一卡片的局部快照，保留静态文本。Electron 首次返回空树或很少元素时，可用较长超时重新读取一次。
- 轮播、弹窗等会替换元素。遇到 `STALE_REF`，先看动作是否已送达；确定未送达后，重新查找当前可见控件，核对其上下文再点击。
- 文字不足时，用 MCP 的 `desktop_screenshot` 只截目标窗口。客户端若只显示尺寸，使用 `output_path` 将 PNG 存入当前任务的临时工作目录，用图像查看工具打开该文件。截图仍由 MCP 获取。仅在与任务相关时保留或交付截图。
- 点击可能只返回 `delivered_unverified`。立即读取页面状态提示、按钮新状态或相关记录；短暂提示可用 `desktop_wait` 等待。送达情况不明或已送达时，先查结果再决定是否需要下一步。领取积分时，“领取成功”能证明领取完成，具体数量应取自同一奖励的标注或到账记录。
