# Windows 桌面操作

优先使用 `agent-desktop` MCP。先按应用名调用 `desktop_list_windows`，用返回的 `window_id` 限定后续查找。只有多个窗口都可能是目标时，才需要按标题或界面内容进一步区分。工具前缀可能随客户端而变化。

## 找到应用窗口

- 有目标窗口就直接读取，最小化时可按窗口 ID 还原。应用尚未运行时，通过已确认的程序名或本机安装路径启动；只有标题、关键词或用户输入的近似拼写时，先核对实际应用名。
- `desktop_launch` 返回 `AMBIGUOUS_TARGET` 时，重新按应用过滤窗口。Electron 的多个进程可能只对应一个窗口。没有窗口时，可通过 MCP 检查已显示的任务栏或托盘入口；找到对应项就唤出窗口并重新枚举。Windows 上 `no_attach` 无法解决已有实例的问题。
- 如果这些入口不可用，简要说明卡在哪一步。用户允许备用工具且当前权限允许时，仅用它唤出已安装的目标应用；窗口一出现就回到 MCP。用户明确要求只用 MCP 时，说明具体阻碍，请用户唤出窗口。遵守客户端的权限限制。

## 阅读界面

- 已知控件文字时，优先按 `window_id` 和 `name` 调用 `desktop_find`，需要时加 `role`。首次查找超时、界面树只读到窗口外壳，或预期可见的控件没有匹配时，下一步用 `desktop_screenshot` 查看目标窗口。
- 截图显示加载占位时，等主界面就绪再读取一次。已知就绪标志时可用 `desktop_wait`，并在参数支持时限定到目标窗口。复查仍超时或只读到外壳时，查看目标窗口有无变化。持续白屏或停在加载画面且没有可见进展时，转入窗口恢复，避免反复查找或聚焦。
- 截图已有内容时，先从画面判断目标区域和可见状态。仍需操作时，按该区域和当前控件文字做一次定向查找。轮播或弹窗换了内容时，先确认当前界面，再依据新状态定位。
- 截图只截目标窗口。客户端若只返回尺寸，用 `output_path` 把 PNG 存入本次任务的临时目录，再用图像查看工具打开。

## 恢复窗口

- 先按应用名重新枚举窗口。窗口最小化时还原，已有可读窗口时直接使用。有任务栏或托盘入口时，按当前能力尝试唤出窗口。
- 确认本次启动的实例持续无进展，且正常退出不会中断已有工作时，可正常关闭后重开一次。关闭返回 `delivered_unverified` 或超时时，用 `desktop_list_windows` 和 `desktop_list_apps` 核对窗口与应用状态。窗口与应用列表均无结果时，可以尝试重开一次。若启动仍返回 `AMBIGUOUS_TARGET`，或主窗口隐藏而应用仍在，按「找到应用窗口」处理。原窗口仍可见且无响应时，报告阻碍。
- 强制关闭需要用户明确授权。正常恢复仍未得到可操作界面时，说明卡在哪个状态，以及任务的哪一步尚未执行。

## 操作与核对

- 签到或领取前，先核对同一张卡片上的活动、奖励和当前状态。多个活动共用「立即领取」时，读取对应卡片的局部快照，保留静态文本。目标卡片明确显示「已领取」时，直接报告页面状态。
- 遇到 `STALE_REF` 时先核对动作是否送达。确认未送达后，重新定位当前可见控件，核对上下文再操作。
- 点击返回 `delivered_unverified` 或送达不明时，先查看页面提示、按钮状态或相关记录。短暂提示可用 `desktop_wait` 等待。积分数量以同一奖励的标注或到账记录为准。
